# 워크플로우

1. `git status` 명령을 사용해서 기존 파일의 변경 사항 및 새롭게 생성된 파일을 인지합니다, 변경사항이 없는 경우 작업을 종료합니다.
2. 변경사항과 세션 컨텍스트를 통해 현재 어떤 작업이 진행되었는지 확인합니다.
3. 커밋 메시지의 작성 형식을 정확하게 파악합니다. [참조](#메세지-포맷)
4. 진행된 작업의 종류가 다수인 경우 변경사항을 다수의 파트로 분류합니다.
5. `git add` 명령을 사용하여 한 파트를 스테이지 상태로 옮깁니다.
6. 작성 형식을 준수하며 30자 이내의 커밋 메시지를 생성합니다. 작업 내역이 완벽하게 커밋에 드러나지 않아도 괜찮으니 간결성을 최우선합니다.
7. `git commit` 명령을 사용하여 커밋 메시지와 변경 내역을 커밋합니다.
8. 4~7단계를 모든 변경사항이 사라질 때까지 반복합니다.

# 메세지 포맷

커밋 타이틀은 아래의 접두사중 하나를 반드시 사용합니다.
작성하려는 커밋의 작업 성향에 맞는 이모지를 적절하게 선택합니다.

- ✨ Feat: 새로운 기능 추가
- 🐛 Fix: 버그 수정
- 💄 Design: UI(CSS) 수정
- ✏️ Typing Error: 오타 수정
- 🚚 Mod: 폴더 구조 이동 및 파일 이름 수정
- 💡 Add: 파일 추가 (ex- 이미지 추가)
- 🔥 Del: 파일 삭제
- ♻️ Refactor: 코드 리펙토링
- 🎉 Init: 프로젝트 세팅
- 🚧 Chore: 배포, 빌드 등 기타 작업
- 🔀 Merge: 브랜치 병합

콜론뒤로 공백을 하나 만들고 타이틀 메세지를 작성합니다.
커밋예시

```
// 타이틀
✨ Feat: 로그인 기능 추가

// 메세지
로그인 모듈을 추가했습니다.
...
```
